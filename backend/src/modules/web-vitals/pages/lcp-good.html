What changed? It's the same 1.2s image from the same server.
  1. Critical CSS is inline, and the slow stylesheet loads without blocking render.
  2. The <img> is in the HTML, so the browser starts downloading it right away. No JS or API call is in front of it.
  3. No loading="lazy" on the hero, and fetchpriority="high" instead.
LCP ≈ image download time (~1.2s) instead of CSS + JS + API + image chained one after another.

Tip: don't click or scroll until the image appears. User input stops LCP measurement.
