2 · Web Components

Each team ships a script that registers a Custom Element (<team-products>, <team-cart>). The shell just writes the tags. Everything runs in one document, but each component renders into its own Shadow DOM.

  • Communication: "props down, events up". The shell sets the currency attribute, listens for add-to-cart events, and calls cart.add(product).
  • CSS isolation: both teams use bare h2/button selectors, and so does the shell. Shadow DOM keeps them apart, so each team keeps its own colours and the shell's purple buttons don't leak in. Inherited properties like font and color do still flow in.
  • Framework-agnostic: the shell doesn't know or care what each team built its element with.
  • Failure: <script onerror> tells the shell which team failed. The :not(:defined) CSS shows a placeholder until the element is defined.
  • Gotcha: the custom element registry is global. Two teams defining the same tag (or two versions of one) will throw.
