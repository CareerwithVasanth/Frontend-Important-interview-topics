3 · Native ES modules + import maps

No bundler and no framework at runtime. Each team deploys an ES module that exports mount(el, props). The shell loads it with import('@team/cart'), and the import map turns that name into a URL. This is the idea behind single-spa and import-map-overrides.

  • Communication: pub/sub through a shared @shop/event-bus module. Products emits cart:add, and Cart subscribes. Neither team imports the other, and the shell doesn't relay anything.
  • Shared dependencies: both teams import @shop/event-bus, which maps to one URL, so they get one module instance. Compare the bus #id in each badge.
  • CSS: no isolation. Products' headings should be teal and dashed, and the shell's own h2 should be plain black. Look at them now: the cart team's global h2/button rules loaded last and restyled the whole page.
  • Failure: import() returns a promise, so try/catch around it gives a clean fallback.
  • Deploy: releasing a team means changing its URL in the import map (often generated by a server). The shell code doesn't change.
